> 固件日志：`firmware/BF7LA6000KF/observice*.log`、`firmware/BF8LA60006M/observice*.log`、`firmware/AZEC8640145/EGO_20261118_135945.log`

## 一、缺陷摘要（提单一句话）

预览关闭后，配对组的 SD 录制参数没有统一选择（`selected_index=-1`，回退到各设备保存的 `saved_sd_profile`）。此时按**设备实体键**起录会绕过参数预检：主机进入 `recording_starting`、但控制设备始终不上报 `recording_started` / elapsed timer，20 秒后主机以 `recording_elapsed_timer_not_started` 超时并补发 stop。界面没有真正的录制会话，用户点"停止录制"没有可停止对象；同时控制设备 AZLV96100A7 残留上一次录制的 `recording_duration_ms=237226` 与 `error_flags=0x20000/0x20020` 达 **2 小时 45 分**，使录制计时/状态停在旧值不前进。

**用户可见结论：设备能录（写卡正常），软件不进录制态、停不下来；计时停在某个值不再变化。**

> 说明：本次导出内**没有一条录制达到 610 s（10:10）**，最长有效录制为 `406001 ms`（6:46，15:02:46，`7354e75aa0`）。"10:10 不能动"的精确落点需要补采控制设备固件日志与冻结瞬间的界面截图/录屏，详见 §六。

## 三、复现步骤（按用户描述整理）

1. 三台设备（1 主 + 2 从）接入同一台 PC，组成配对组，三张 SD 卡均正常。

## 五、根因分析

```
预览关闭
  └─ 没有预览参数 → SD 参数回退到各设备 saved_sd_profile
       └─ 三台设备保存值不一致（主 H264 / 从 H265），selected_index=-1（"非限制"）
            ├─ 主机点击起录：被 preflight 拦截（正确）
            └─ 实体键起录：仍按 mismatch 起录（BUG-1 未修复，2.0.25 仍存在）
                 ├─ 控制设备 AZLV96100A7 状态机未推进（work_state 始终 2）
                 │    └─ 主机收不到 recording_started / elapsed timer
                 │         └─ 20 s 超时 sd_recording_start_timed_out，
                 │            然后才补发 stop
                 ├─ 从设备从未收到 record 命令（BF7/BF8 无 record pipe）
                 └─ 界面没有真实录制会话 → 停止按钮没有可停止对象
                      └─ 用户感知：能录、停不下来

叠加因素：
  - AZLV96100A7 残留 recording_duration_ms=237226 + error_flags=0x20000/0x20020
    持续 2h45m，直到 13:58 设备复位才清掉 → 计时/状态停在旧值
  - 固件每次停止都出现 RecordCommandPipe 打开失败 → 停止链路存在单点故障
  - 设备在参数不一致时用 0x80000 (recording_aborted) 告知主机，但主机的
    "终止锁存"与"清除录制态"行为仍不完整（与 11/11 缺陷同源）
```

### 核心结论

1. **设备侧"能录"是真的**：14:55:53 那次三机都写卡，`persistence_ok=1`。
2. **主机侧"停不下来"也是真的**：7 次实体键起录中，控制设备从未进入 recording，主机等 20 s 才补发 stop；这 20 s 内界面是"起录等待"而不是"录制中"，用户没有正常的停止入口。
3. **参数不一致不是唯一触发条件**：14:03:05 预检 already `passed`，依然 timed out，说明控制设备状态机/计时上报本身存在缺陷。
4. **残留时长是"计时卡死"的直接嫌疑**：`recording_duration_ms=237226 valid=true` 在 ready 状态下保留了 2h45m，主机侧计时/状态会以它为准。

## 九、结论

> **设备能录、主机没进入录制态；停止链路与状态清理存在缺陷。**

- 预览关闭不是根因，参数未统一 + 实体键绕过预检是触发条件；
- 控制设备 AZLV96100A7 的状态机停在 ready、并残留 3:57 的旧录制时长达 2 小时 45 分，主机因此等不到 elapsed timer，20 s 后才补发 stop；
- 用户看到的"停不下来 / 计时不动"与这条链路一致；"10:10"的精确落点需要补采控制设备固件日志与界面录屏；
- 固件每次停止都报 `RecordCommandPipe` 打开失败，是一条需要单独修的停止链路隐患。
