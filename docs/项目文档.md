# EGO Courier · 项目文档

> EGO 采集日志的收发与完整性分析工具：从设备 / EGOViewer / 手机收拢日志，并对录制目录做同步、丢帧、音频与元数据完整性分析，输出自包含 HTML 报告。
> 本文档面向开发者，描述项目定位、技术栈、功能、架构与实现要点。

---

## 1. 项目定位

TN2608 / EGO 系列设备录制时会产生多种带时间戳的数据：相机 CSV、IMU CSV、MP4/MCAP 视频流、WAV 音频、`meta_*.json` 元数据。现场需要：

1. **把日志收回来**：从 EGOViewer 本机目录、手机（adb）、设备固件（Orbbec SDK）收集；
2. **判断录制是否完整**：相机帧数、帧间隔、跨相机同步、IMU 同步与丢帧、音频包完整性与时长、跨录制段边界、元数据完整性；
3. **形成可交付的结论**：一份自包含 HTML 报告。

**EGO Courier** 把这两件事放在同一个桌面工具里完成。

---

## 2. 技术栈

| 层 | 技术 |
|---|---|
| GUI | PySide6（Qt 6，Fusion 风格 + 手写浅色 QSS） |
| 分析引擎 | `ego_checker/`（内嵌 EGOChecker 分析内核，纯 Python + numpy） |
| MCAP | `mcap` + `lz4` / `zstandard`（压缩流） |
| 设备通道 | paramiko（SFTP）、adb（手机）、Orbbec SDK（固件日志）、BLE（配网） |
| 报告 | 标准库生成自包含 HTML（内联 CSS/JS） |

不再依赖 matplotlib：分析结果只出 HTML 报告与 GUI 表格，没有曲线图。

---

## 3. 形态

| 形态 | 入口 | 说明 |
|---|---|---|
| 桌面版 | `EGO Courier.bat` / `python run_desktop.py` | 三个页签：**日志导出**、**日志分析**、**会话记录** |
| 便携版 | `EGO Courier.exe` | 自带 Python 与依赖，解压即用 |

没有独立命令行工具：分析只通过 GUI 使用，导出通道的底层函数由 GUI 调用。

## 4. 架构

```
┌──────────────────────────────────────────────────────────┐
│ ego_gui/                                                   │
│   main.py        窗口入口 + 图标 + 浅色调色板               │
│   app.py         主窗口 / 全局 QSS / 页签 / 跨页联动         │
│   device_tab.py  日志导出页（BLE 配网 + 三类日志一键导出/打包）│
│   analysis_tab.py 日志分析页（AnalyzerWorker → AnalysisTask） │
│   analysis_schedule.py 定时分析设置 / 触发控制器                │
│   history_tab.py  会话记录页（分析历史：筛选/详情/对比）        │
│   export_tab.py  BLE 扫描后台线程                           │
└───────────┬───────────────────────────────┬──────────────┘
            │ 设备侧                         │ 分析侧
┌───────────▼──────────────┐   ┌────────────▼─────────────────┐
│ ego_relay/               │   │ ego_checker/                  │
│  evlog_pack  本机日志     │   │  app/       发现分段 + 编排     │
│  mobile_adb  手机 adb     │   │  analysis/  同步/丢帧/边界/音频 │
│  orbbec_sdk  固件日志     │   │  data/      CSV/MCAP/音频/meta │
│  egolowble / ble_provision│   │  media/     SEI/截帧/ffmpeg    │
│  wifi / sftp_client       │   │  reporting/ HTML 报告与表格     │
│  config / deps            │   │  domain/    模型与常量          │
└──────────────────────────┘   │  runtime/   路径/版本/运行日志   │
                               └───────────────────────────────┘
```

**分层原则**：GUI 只负责交互与呈现；设备通道封装在 `ego_relay`，分析逻辑封装在 `ego_checker`。

### 4.1 运行数据

- `data/`（源码模式）或 exe 同级 `data/`（打包后）：导出目录、临时解压、`tab_order.json`、分析运行日志 `data/log/analysis_*.log`、分析历史 `data/history/sessions.json`。路径由 `ego_relay/config.py` 的 `DATA_ROOT` 与 `ego_checker/runtime/paths.py` 的 `data_directory()` 共同决定（后者复用前者）。
- 定时分析配置：`data/analysis_schedule.json`（原子写入）；单实例锁 `data/analysis_schedule.lock`（QLockFile），保证同一时间只有一个窗口执行定时任务。
- 增量导出记录：`data/export_incremental.json`（原子写入）按 EGOViewer 根目录保存 app/SDK 的上次成功导出结束时刻；「只导新增日志」用它作为下次收集的起点，手机/固件日志不参与增量。

### 4.2 分析流程（`ego_checker/app/workflow.py` 的 `AnalysisTask`）

1. `discover_parts`：扫描数据根目录，按 CSV / MCAP / JD / 音频发现录制分段（part），并按单设备 / 多设备、落盘格式、配对等级分组；
2. 逐段 `analyze_part`（可并行子进程，`app/parallel.py`）：读取时间戳、执行各项检查、做跨段边界样本提取；
3. 跨段补偿：IMU 与相机的相邻段同步（流式滑动窗口或全量）；
4. 白名单（GUI 不使用）与可选 SEI 对齐 / 帧截取；
5. `reporting/outputs.py` 生成 HTML；`reporting/columns.py` 提供 GUI 表格的列与单元格（`row_cells` / `row_details`）。

进度与日志通过回调抛出；GUI 用 `QThread`（`AnalyzerWorker`）把日志、进度、完成、失败、停止转成 Qt 信号。用户停止时 `AnalysisTask` 仍生成部分报告。

**定时触发**：`ego_gui/analysis_schedule.py` 的 `ScheduleController` 每 30 秒按本机 wall clock 检查一次计划时刻（每天 / 仅一次，支持 2 小时补跑与 `last_trigger_for` 防重复）；到点后用保存时的参数快照调用同一个 `_run_analysis` 入口，因此定时与手动分析共用同一套结果、历史与报告流程。定时数据目录支持多个（`data_roots` 列表），由 `AnalysisTab` 逐个排队执行，每个目录一个独立输出子目录；多目录结果在 `last_run.runs` 里逐条记录。定时分析要求 EGO Courier 进程保持运行。

## 5. 主要模块

### ego_relay（设备侧）

| 文件 | 职责 |
|---|---|

| `orbbec_sdk.py` | 通过 Orbbec SDK 拉取设备固件日志 |
| `egolowble.py` / `ble_provision.py` | BLE 扫描与 Wi-Fi 配网 |
| `wifi.py` | Wi-Fi 扫描与 ping |
| `sftp_client.py` / `sftp_pull.py` | SSH/SFTP 拉取远端日志 |
| `deps.py` / `deps_check.py` | ffmpeg/mcap 等运行依赖探测与启动器依赖清单 |
| `history.py` | 分析历史登记簿（JSON 原子写入、去重、缺失标记，供会话记录页） |

### ego_checker（分析侧）

| 包 | 职责 |
|---|---|
| `app/` | `workflow` 编排、`analyzer` 单段分析、`parallel` 多进程、`options` 参数解析 |
| `analysis/` | `timing` 同步与丢帧、`context` 跨段参考、`boundaries` 边界、`audio`/`waveform` 音频 |
| `data/` | `csv_readers`、`mcap`、`audio` 读取、`discovery` 分段发现、`meta_integrity` |
| `media/video.py` | SEI 提取、帧截取、ffmpeg 调用 |
| `reporting/` | `outputs` HTML、`columns` GUI 表格、`boundaries`、`evidence`、`audio` |
| `domain/` | `models` 结果模型、`constants`、`numeric` |
| `runtime/` | `paths`、`version`（跟随 EGO Courier 版本）、`run_log`、`control` |

## 6. 检查项与口径

见根目录 README「分析能力（内嵌 EGOChecker 引擎）」一节的表格。要点：

- 相机帧数对齐、帧间隔波动、同行对齐、相机同步、IMU 同步、RGB 丢帧、IMU 丢帧/倒退、音频完整性、元数据完整性；
- 阈值支持「自适应」（按帧率与 IMU 频率）与「固定输入」两种模式；
- 可选 SEI 时间戳对齐与帧截取（需要 ffmpeg）。

---

## 7. 输出

- **一份自包含 HTML 报告**（默认写入输出目录，未指定时写入数据根目录下的 `fsync_output`）。
- GUI「分析结果」表格：PASS/FAIL 着色，双击单元格查看异常明细。
- 分析完成/停止弹窗：列出问题 Part（异常 / 执行异常 / 未验证）及失败的检查项，
  可「定位异常 Part」在结果表中选中并在 HTML 报告中跳到对应明细行；
  HTML 报告顶部同时提供「问题 Part 快速定位」链接。
- 不写数据库、不生成结果 CSV、不生成独立证据目录。
- **会话记录**（`ego_relay/history.py`）：每次分析结束在 `data/history/sessions.json`
  追加一条记录（状态 finished/partial/failed、统计、Part 摘要、设备名、报告与目录路径、
  备注）。只存路径与统计，不复制报告；报告或数据目录失效时在页面上标为「缺失」，
  记录本身保留。

---

## 7.1 会话记录页（`ego_gui/history_tab.py`）

与「日志分析」页分工：分析页负责**跑**，会话记录页负责**留存与追溯**。

- 列表：时间 / 结论 / Part 数 / 异常 / 设备 / 数据目录 / 报告是否可用 / 备注，
  支持按结论、数据源（导出目录 vs 手动目录）、报告缺失、关键字（设备/目录/备注）筛选。
- 详情（页内抽屉 + 返回列表）：统计卡 + Part 明细表（结论按 PASS/FAIL/ERROR 着色）
  + 来源文件（数据/输出/报告/设备路径）+ 备注编辑；可打开报告、按此目录重新分析。
- 对比：选中两条记录并排看统计差异，以及同名 Part 的结论差异。
- 删除：默认只删记录；可选同时删报告文件；**数据目录永远不删**。
- 写入在后台线程完成，不阻塞分析结果展示；同一分析的重复回调自动去重。

## 9. 变更说明

本版本把日志分析整体切换为内嵌 EGOChecker 引擎，并移除旧分析实现：

- **移除**：`ego_relay/analysis.py`、`parsers.py`、`db.py`、`export.py`、`compare.py`、`cli.py`、`video_analyzer.py`、`cache.py`；`ego_gui/sessions_tab.py`、`trace_tab.py`、`import_tab.py`、`charts.py`、`report.py`、`session_view.py`；`ego.bat`。

- **改动**：`device_tab.py` 去除导出后的自动导入分析 / 生成报告，导出完成后把目录预填到分析页；`deps_check.py` / `requirements.txt` 移除 matplotlib、补充 lz4/zstandard；构建 spec 打包 `ego_checker` 资源与子模块。
