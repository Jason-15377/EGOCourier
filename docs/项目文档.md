# EGO Courier · 项目文档

> 轻量日志中转网关，用于收拢 TN2608 / EGO 双目设备的四类日志，自动按帧对齐、计算时间戳差值、检测异常，并提供桌面查询与一键打包导出。
> 本文档面向新加入的开发者，描述项目定位、技术栈、功能、架构与实现细节。

---

## 1. 项目定位

TN2608 / EGO 双目相机在采集与回放过程中会产生多类带时间戳的日志，彼此分散、格式不一、时间基准各异。人工核对双目同步、SEI 校验、应用接收延迟、IMU 数采同步等问题非常繁琐。

**EGO Courier** 把这些日志收拢到一个工具里：

- 自动**按帧对齐**四类时间戳来源，统一归一化到**硬件 PTP 时间戳（微秒 epoch UTC）**为真值基准；
- 计算任意两两来源的时间戳差值，**超过阈值自动标记异常**；
- 提供**桌面 GUI**（PySide6）前端，以及**命令行**工具；
- 支持**一键打包导出**（zip + HTML 报告 + 异常截帧）。

一句话概括：**"把相机日志对齐、算差、标异常、可查询、可导出"** 的中转/分析网关。

## 2. 技术栈

### 2.1 总体
- **语言**：Python 3（纯 Python 实现）。
- **核心包 `ego_relay`**：**除个别模块外全部使用 Python 标准库**（`csv` / `re` / `sqlite3` / `json` / `zipfile` / `tarfile` / `bisect` / `argparse` / `subprocess` / `ctypes` / `threading`）。

### 2.2 依赖一览

| 层 | 依赖 | 用途 |
|---|---|---|
| 核心存储 | `sqlite3`（stdlib） | 会话/帧/异常数据持久化，WAL 模式 |
| 桌面 GUI | **PySide6** | 全部界面（QtWidgets/QtCore/QtGui） |
| 图表 | **matplotlib**（QtAgg 后端） | 时间偏移曲线 + 丢点/丢帧柱状图 |
| 远程拉取 | **paramiko** | SSH2 + SFTP 从设备拉日志 |
| 蓝牙配网 | 系统 **EgoLowBle.dll**（经 `ctypes` 调用） | BLE 下发 Wi-Fi 配置 |

桌面版一键安装依赖：
```bat
python -m pip install PySide6 matplotlib imageio paramiko
```

### 2.3 数据基准
- **真值基准 = 硬件 PTP `hw_ptp_ts`（epoch 微秒 UTC）**，其余三类时间戳统一归一化到微秒并与之对齐/求差。
- 时间戳单位按数量级**自动判定**（ns / us / ms）。
- EGOViewer 应用日志本地时区偏移 `VIEWER_TZ_HOURS = 8`（UTC+8）。

## 3. 功能总览

### 3.1 输入（四类日志）
| 类型 | 匹配文件 | 提供的时间戳 |
|---|---|---|
| 硬件 PTP | `*_sei.csv` | `hw_ptp_ts`（帧硬件时间，真值） |
| MP4 视频帧内 | `*_pts.csv` | `sei_hw_ptp_ts`（SEI 嵌入校验） |
| IMU 数采 | `*_imu*.csv` | `imu_sample_ts`（最近 IMU 时刻） |
| EGOViewer 应用日志 | `ego-viewer-*.log` / `orbbec*.log` | `app_local_receive_ts` + `trace_id`(sessionId) |

文件发现：按 `SOURCE_PATTERNS` 的 glob 规则**递归扫描**目录（或解压 zip），单个文件解析失败**不阻塞整包**（容错导入）。

### 3.2 对齐与异常（四类规则）
以硬件 PTP 的 `frame_index` 为主线合并多路时间戳，IMU 用最近邻（`bisect`）匹配。

| 规则 | 计算 | 默认阈值 |
|---|---|---|
| `app_receive_delay` | \|app 接收时刻 − hw_ptp\| | 50 ms |
| `sei_copy_error` | \|sei_hw_ptp_ts − hw_ptp_ts\|（SEI 校验） | 2 ms |
| `binocular_ptp_diff` | \|left.hw_ptp − right.hw_ptp\|（同帧号，双目同步） | 1 ms |
| `imu_video_sync` | \|最近 IMU − hw_ptp\|（数采同步） | 2 ms |

阈值**可配置**（GUI 阈值页 / CLI `ego thresholds set`），修改后对当前会话**就地重算**。

### 3.3 采集质量统计
- IMU 丢点/占比（按间隔中位数估算）
- 视频丢帧/占比（帧号连续性）
- PTP 异常片段（连续超阈值区间）
- 丢帧率、左右同步均值、IMU-视频均值、traceID 匹配情况

### 3.4 异常自动截帧
对每条异常，按异常帧的**硬件 PTP 时间戳**匹配会话目录下 `frame_dumps/**/*.jpg`（文件名以 `_<hw_ptp_us>.jpg` 结尾、`_left_/ _right_` 区分侧）：精确匹配优先，无精确时取 500ms 容差内最近一帧。截帧入库（`anomalies.frame_image`），GUI 显示缩略图，导出时打包进 `anomaly_frames/`，报告内以 base64 内嵌。

### 3.5 关联 EGOViewer app 日志（attach-log）
会话只有 SEI/MP4/IMU（无 app 日志）时，可单独关联 `ego-viewer-*.log`，获得 `trace_id` 与应用接收时刻，从而让 `app_receive_delay` 可计算。系统把日志**复制进附件区**（不修改原始数据）、加入 `log_files` 并**就地重算**，重复关联幂等。

> **已知限制**：EGOViewer 日志的 `frameIndex` 是设备全局帧计数，SEI 会话的 `frame_index` 是会话内相对编号，二者不一定时间对齐。仅当 app 日志与 SEI 会话属**同一次录制**时 `app_receive_delay` 才准确；否则差值大、被标异常——这本身也能提示"日志与数据不匹配"。

### 3.6 两种前端
| 形态 | 入口 | 说明 |
|---|---|---|
| **桌面版** | `EGO Courier.bat` / `python run_desktop.py` | PySide6 GUI：通用导入、会话记录（概览/帧对齐/异常/Trace 四子页）、阈值、Trace 查询、WiFi 扫描、BLE 配网 + SSH/SFTP 导出、底部日志框 |
| **命令行** | `ego <子命令>` / `python -m ego_relay.cli` | 导入/查询/导出/阈值/WiFi 等 |

### 3.7 导出
一键打包 zip，内含：
- `raw/` —— 原始来源文件
- `summary.json` —— 会话元数据 + 统计 + 阈值
- `frames.csv` —— 对齐帧表（UTF-8-sig）
- `anomalies.csv` —— 异常表
- `anomaly_frames/` —— 异常截帧 jpg
- `report.html` —— 自包含 HTML 报告（截帧 base64 内嵌，前 300 条异常）

### 3.8 设备交互
- **WiFi 扫描**：本机周边环境信息（SSID/信号/安全/连接状态），`netsh wlan` + 多编码容错。
- **BLE 配网**：`EgoLowBle.dll` 下发 Wi-Fi 配置、轮询设备入网取 IP（预留，需真机校验）。
- **SSH2 + SFTP 拉取**：`paramiko` 实现，支持远端 `tar -czf` 先压缩再下载（省流量）、递归下载、进度回调、拉取后自动导入。

## 4. 架构

```
                    ┌─────────────────────────────────────────────┐
  四类日志           │              ego_relay 核心包                │
 (目录/zip) ───────▶ │  config → parsers → analysis → db(DB)      │
                    │                          │                  │
                    │                          ▼                  │
                    │        export.py      cli.py (命令行)        │
                    │        (zip+HTML)                           │
                    └─────────────────────────────────────────────┘
                                     │  ▲
                                     ▼  │
                              ego_gui 桌面版
                           (PySide6, 只负责呈现,
                           逻辑下沉到核心包)
```

**分层原则**：GUI / CLI 两种前端都只负责**呈现与交互**，所有"重活"（解析、对齐分析、存储、SFTP、BLE、WiFi）都封装在 `ego_relay` 核心包中，两种前端复用同一套逻辑。

### 4.1 数据模型（SQLite，`db.py`）
| 表 | 说明 |
|---|---|
| `devices` | 设备 |
| `sessions` | 会话（一次导入 = 一个会话） |
| `log_files` | 会话内的来源文件 |
| `frame_entries` | 核心对齐表：每 `(side, frame_index)` 一行，存 hw_ptp / sei_hw_ptp / app_recv / imu 四类微秒时间戳 + trace_id |
| `anomalies` | 异常：rule / frame_index / ts_a / ts_b / delta / threshold / severity / frame_image |
| `trace_sessions` | trace_id 与会话关联 |

连接管理：`threading.local()` 每线程独立连接 + 全局写锁；`journal_mode=WAL`、`foreign_keys=ON`。DB 位于 `data/ego_relay.db`，阈值持久化在 `data/thresholds.json`。

## 5. 核心模块职责

### 5.1 `ego_relay`（核心包）
| 模块 | 职责 |
|---|---|
| `config.py` | 全局配置：路径、时区、设备信息、异常阈值、字段别名、文件发现规则、阈值持久化（`data/thresholds.json`） |
| `db.py` | SQLite 存储层：建表、迁移、会话/帧/异常读写、重置 |
| `parsers.py` | 四类解析器 + 时间戳归一化；`import_path` 统一导入入口（目录/zip） |
| `analysis.py` | 帧对齐 + 四类异常计算 + 质量统计 + 截帧回填 + 重算/关联 |
| `export.py` | 一键打包导出（zip + HTML 报告） |
| `cli.py` | `argparse` 命令行入口 |
| `wifi.py` | Windows `netsh wlan` WiFi 扫描与状态 |
| `egolowble.py` | `EgoLowBle.dll` 的 ctypes 包装（ABI 未真机校验，风险点） |
| `ble_provision.py` | BLE 配网编排（扫描/连接/配网/取 IP） |
| `sftp_client.py` | `paramiko` SSH2 + SFTP 客户端（连接/远端打包/下载/清理） |
| `sftp_pull.py` | 拉取 + 自动导入编排（多目录 `&` 分隔） |

### 5.2 `ego_gui`（桌面版）
| 模块 | 职责 |
|---|---|
| `main.py` | 入口：`QApplication` + 手绘摄像头图标 |
| `app.py` | 主窗口、全局 QSS 样式、底部日志框、跨页联动信号 |
| `import_tab.py` | 通用导入（`QThread` 后台解析 + 来源文件表） |
| `sessions_tab.py` | 会话列表 + 详情面板（最重，551 行：统计卡、四子页、导出、重算） |
| `thresholds_tab.py` | 阈值调整（保存后即时重算当前会话） |
| `trace_tab.py` | trace_id 查询 |
| `export_tab.py` | BLE 配网 + SSH/SFTP 导出（三个 `QThread` Worker） |
| `wifi_tab.py` | WiFi 扫描 |
| `report.py` | 自包含 HTML 报告（内嵌 matplotlib 图） |
| `charts.py` | matplotlib 2 子图（偏移曲线 + 丢点/丢帧柱状图），QtAgg 嵌入 |

GUI 全部通过 `from ego_relay import ...` 调用核心包，不复制任何核心逻辑。

## 6. 命令行（`cli.py`）

```bat
ego list                                                     列出会话
ego import "D:\...\EGO_AK8896100BJ_20260915_143309"         导入目录/zip 并分析
ego show 1                                                  会话详情 + 异常汇总
ego query 1 --anomalies                                     查看会话 1 的异常
ego query 1 --side left --anomaly-only                      查看左目异常帧
ego export 1 -o out.zip                                     一键打包导出
ego attach-log 1 "path\ego-viewer-2026-09-15.log"           关联 app 日志并重算
ego thresholds show / set <rule>=<us> ...                   查看/调整阈值
ego wifi --scan                                             扫描 WiFi
ego status                                                  健康检查
ego device pull ...                                         预留：设备 WiFi 导出（通道未配置）
ego ble status|scan|provision                               BLE 配网
```

## 9. 已知限制 / 待办

- `ego device pull` 为**预留占位**：设备 WiFi/网络导出通道待确认接口（ADB / SMB / HTTP）后实现。
- `EgoLowBle.dll` 的 ABI 定义**未经真机校验**（`egolowble.py` docstring 已明确警告），需接入真实设备验证。
- 设备 SSH 凭证默认为空（`config.py` 中 `DEVICE_IP / SSH_USER / SSH_PASSWORD`），当前以本地导入为主。
- `app_receive_delay` 需要同会话同时具备 app 日志 + 硬件 PTP 才能计算；缺任一时该规则自动跳过，不影响其余三条规则。
- EGOViewer 日志与 SEI 会话的帧计数基准不同，关联时需同次录制（见 3.5）。
- 后续迭代：AI 日志总结。
