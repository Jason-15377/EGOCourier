## EGO Courier v1.0.9

本版修复 **导出过程收不住、导错设备、手机日志看不全** 三类现场问题：失败后进度条卡死无法取消、以太网设备被误当成自己的设备混进结果、手机导出包里从设备的日志要手工解压才看得到。另附 BLE 扫描与配网连接的大幅提速。

### 一、导出失败后无法收尾（影响最大）

**现象**：手机掉线导致导出失败（`adb: error: failed to get feature set: device 'XXX' not found`）后，进度条停在失败那一刻的百分比；点「取消任务」只往日志写一句「当前没有运行中的导出任务」，进度条永远卡着，只能重启程序。

**原因**：失败处理只写日志、从不复位界面，而 `_stop()` 在 worker 已结束（`isRunning()` 为假）时不走任何复位分支。

**修复**：
- `_on_export_fail` / `_on_pack_fail` 与取消、完成一样清空进度条（`_reset_progress`，同时丢弃节流缓存）；`_stop()` 在无运行任务时也执行复位并恢复按钮。
- 取消不再干等：`adb pull` 单次最多阻塞 900 秒，原先只在调用前后检查取消标志。现改为 `Popen` + 300 ms 轮询，取消即 `terminate`（超时兜底 `kill`），取消事件贯穿整个拉取链路。
- 半成品目录自动清理：取消或失败时删除**本次**创建的 `EGO_export_<时间戳>/`（只删这一个，不碰输出根目录下别的产物），避免下次被当成一次真实导出。

### 二、只导出电脑 USB 直连的设备

**现象**：只插了 2 台 USB，导出却拉了 5 台。原因是配网框里留着 IP，SDK 就按「同网段」把 `192.168.1.x` 上的以太网设备也一并拉了。

**修复**：以太网/Wi-Fi 上的设备属于谁，SDK 信息判断不了（同网段既有自己的从设备，也有别人机器上的设备），靠网段、延迟、历史都只能是猜，结果时多时少。现在：
- **自动模式只导 USB 直连设备**，以太网/Wi-Fi 一律不导，并在日志里逐台列出被跳过的设备与 IP；
- 配网 IP 只影响拉取顺序，不再决定拉几台；
- 一台 USB 都没有（纯网线现场）时退回导出全部可访问设备，避免结果为空；
- **手动勾选**仍视为明确指定，不受此限。

新增「固件设备」行（移到「手机日志」正下方，两者是一组）：点「选择设备…」列出在线设备（含 ping 延迟）与导出历史，勾选后只导这些。默认策略为**历史优先**——记录每台设备成功导出次数与时间（`data/firmware_devices.json`），反复在用的那几台排前面，无历史的才按延迟补位；以太网设备最多 3 台避免拖慢整次导出，USB 直连与手机已覆盖的不占名额。

### 三、手机导出包按设备展开

**现象**：勾了「手机日志」后，从设备（指环 / 手表）的日志看不到——只搬回一个 zip，要人自己解压再翻 `firmware/`。

**修复**：包内 `firmware/<SN>-<时间戳>-<hash>/` 的每台设备解到 `<机型>/<SN>-<时间戳>-<hash>/` 平铺，去掉 `firmware/` 与「固件日志/」两层；手机上残留的 `firmware_logs/` 副本同样平铺。zip 仍原样保留一份备查，解压路径做了 zip-slip 防护。会话记录里的手机目录识别同步修正（新包名 `egoviewer-logs-*` 与平铺分组都能认）。

### 四、设备通信失败可读化

`Device response size(0) < response header size(10)` 这类是 SDK 原样抛出的设备侧故障，不是本工具报错。现在归为 `unresponsive` 类型，给出「重新插拔 / 断电重启、确认 EGOViewer 未占用、网线场景确认能 ping 通」的可操作提示，并保留原文便于贴给研发；这类瞬态错误自动重试一次（间隔 2 秒，可被「取消任务」中断），被占用、固件日志关闭、缺 DLL 等稳定失败不重试。

### 五、配网与扫描提速

- **BLE 扫描 10s → 2.1s**：改为单轮 2 秒、有结果立即返回；一台都没扫到才依次补扫、放宽信号下限、关闭名称白名单。
- **扫不到设备的根因**：早先只比对裸前缀，`EGO-4B_AZL…`、`UMI_Finger-R_…`、`WristCam-R-R_…` 这类真实广播名被过滤掉，表现为「设备在，列表里没名字，重启才出现」。现兼容分隔符，且名称允许为空（地址属于 EGO OUI 的广播不再丢弃，BLE 首包常只带 MAC）。
- **「配置 Wi-Fi 并添加设备」17.6s → 4.3s**：主因不是等 IP，而是直接 connect 要走慢速服务发现（实测直连 17.4 秒，先扫 2 秒再连只要 2.2 秒）。现连接前先预热扫描，IP 轮询改为短超时 + 高频。

### 六、界面

勾选框在 v1.0.8 交回系统绘制后，Windows 11 原生样式（PySide6 6.8 默认）实际不画方框，只剩一条灰细线。现由 QSS 显式绘制：白底 + 1px 灰边 + 3px 圆角，勾选时框内叠加深色 ✓。图案为随包分发的 `assets/check.svg`（QSS 的 `url()` 不认 `data:` URI，实测静默失效），勾选态不改方框底色，不会退回蓝底实心块。
