## 一、缺陷摘要（提单一句话）

**用户在软件中调整的彩色流（Color）图像参数——自动曝光开关、曝光时间、增益、最大曝光、自动白平衡开关、色温——只写进了设备内存（进程内缓存），从未落盘到非易失存储；一旦设备重新上电/服务进程重启，这些参数全部回到固件出厂默认值，用户前一次的调参结果丢失且软件端无任何提示。**

实测证据分两类，指向同一根因：

| 场景 | 用户设置值 | 重新上电/重启后实际值 | 结论 |
|---|---|---|---|
| **从设备 BF8LA60006M 真正断电重启**（14:46:19 → 14:46:42 `AOE Service Starting...`） | exp=**14603**、gain=**8695**、maxExp=**33000**、WB=**7500** | exp=**13000**、maxExp=**10000**、WB=**4500**、gain=**1024** | 全部丢失，回到出厂默认 |
| **主设备 AZL9861004V 彩色流**（11:24 设 maxExp=33000） | maxExp=**33000** | 14:25:40 与 14:37:08 两次开流后变 **16000** | 未持久化 + 开流时被 AE 重初始化覆盖 |

**用户可见结论：调好的彩图曝光/白平衡，关机再开机就全变回默认；甚至只是切换一次分辨率/帧率，最大曝光也会自己变回去。**

## 四、复现步骤

### 4.1 主路径（用户报告的场景）

1. 接入配对组（1 主 + 2 从），打开预览。
2. 在软件中选中 EGO-4B（`72c1a50ee0`），进入彩色流参数面板。
3. 关闭自动曝光 → 手动设置曝光/增益/最大曝光 → 关闭自动白平衡 → 手动设置色温 → 再按需切回自动。
4. **关闭设备电源，重新上电**（或断开 USB 后重连设备）。
5. 重新连接后读取该设备彩色参数面板。

### 4.2 稳定复现的简化路径（不需要断电，10 秒内可见）

1. 选中 EGO-4B，设 `color.maxExposure` = **33000**（默认 16000）。
2. 回到流设置，**只把某路彩色流的分辨率或帧率改一次**（例如 1920×1200@30 → 1600×1200@30）。
3. 再打开参数面板：`maxExposure` 已变回 **16000**，且**全程没有任何提示**。

> 这条路径在本轮日志里出现了两次（14:25:40、14:37:08），每次都在"开流后 5 毫秒内"被改回默认值。

## 六、根因分析（给开发的定位建议）

### 6.1 设备侧（主要责任）

三款设备的彩色参数实现都缺少"写 NVM"环节：

| 设备 | 现象 | 代码位置线索 |
|---|---|---|
| AZL9861004V | `setCameraExposure`/`setCameraGain`/`setCameraWB` 只更新 `cached u32US` / `cached u32SensorGain` / `cached awbMode`，无落盘日志；`initCamParams` 的 `camparams` 只覆盖码流/录制 profile（`regenerated=1 fingerprintMatched=1`），不带 AE/WB 字段 | `Color.cpp:2615 setCameraGain`、`Color.cpp:2652 setCameraExposure`、`Color.cpp:2812 setCameraWB`、`DeviceService.cpp initCamParams` |
| BF8LA60006M | `PARAM-LOAD persistedMask=0x3f iqMask=0xb` 表明有持久化机制，但 **mask 里不含 AE/WB/EXP/GAIN/MAXEXP 字段**；每次开流 `[CTL] [SYNC] syncRange done: gain=1024 exp=13000 aeMode=2 awbMode=1 wb=4500` 都是写死默认 | `Color` 的 `PARAM-LOAD` / `syncRange` |
| BF7LA6000KF | 未暴露彩色曝光属性（0 条 AE 日志），本单不涉及 | — |

`maxExposure` 的复位点更具体：`startCamera` 之后立即 `ISP cam group 0 init success`，5ms 内 `AE-MAX-EXPOSURE-GET` 由 33000 → 16000，且**没有任何 `SET 189` 写入**，属于 AE 模块初始化时直接以默认常量覆盖了缓存，而不是"先读后写"。

### 6.2 主机侧（放大器，非根因）

`OrbbecDeviceSession` 的 `video_encoder_settings_reapply_completed`（码流/编码参数重下发）**只覆盖 video/imu/mag_encoder/audio 四个 domain**，不包含 `color` 图像参数。
因此每次 `stream_configuration_apply`（改分辨率、改帧率、开关流）之后，主机**不会把用户设过的彩色参数重新下发给设备**，导致 5.2 的复位无人纠正：

```
14:37:08.542  video_encoder_settings_reapply_completed device_id=72c1a50ee0
              domains=video requested_count=2 applied_count=2 ...   ← 只有 video，没有 color 图像参数
```

> 换言之：设备"记不住"是根因；主机"重连/重开流后不补写"让问题在每个会话边界都被放大一次。

## 九、修复优先级建议

1. **BUG-1（P1，最高）**：在 `Color` 的 AE/WB setter 之后接入持久化（与 `bitrate`/`recording_format` 同一套 NVM 机制），并在 `initCamParams` 之后按"用户值优先"回填。**这是用户报障的直接原因，必须先修。**
2. **BUG-2（P1）**：`startCamera` 内的 AE 初始化改为"仅在无缓存值时使用默认值"，或在初始化后立即回写缓存的 `maxExposure`。
3. **BUG-3（P1）**：`aeMode` 纳入持久化范围；开流流程不得隐式切 auto。
4. **BUG-4（P2，主机侧）**：`video_encoder_settings_reapply` 增加 `color` domain，作为固件升级前的兜底。
5. **BUG-5（P2，主机侧）**：新增 `device_parameter_changed_by_device` 事件与 UI 提示，避免"参数偷偷变回去"。

## 十、结论

> **设备的彩色图像参数只存在内存里，从没存进 Flash。**

- 用户调过的 `color.exposure / gain / maxExposure / whiteBalance / autoExposure / autoWhiteBalance`，主机侧全部写成功、回读一致，**功能链路是通的**；
- 设备固件（AZL9861004V 与 BF8LA60006M 同型）的 `setCameraExposure/setCameraGain/setCameraWB` **只更新进程内 `cached` 变量，没有落盘动作**；
- 同一份 `observice` 对**码率、录制格式、分片、录制 profile** 都有明确的 `SET <id>:` 落盘日志，唯独彩色 AE/WB 一族（2000/2001/2002/189/2025/色温）不可见——**不是做不到，是这组参数没接进去**；
- BF8 在 14:46:19→14:46:42 真正断电重启后，`exp 14603→13000`、`gain 8695→1024`、`maxExp 33000→10000`、`wb 7500→4500`，而码率/录制参数原样保留，**形成了最直接的 A/B 对照**；
- 更糟的是，主设备侧连"切换分辨率/帧率"这种日常操作都会让 `maxExposure` 在 5 ms 内静默回默认（14:25:40、14:37:08 两次），且主机重开流只补 `video` domain、不补 `color`，**用户完全没有察觉的机会**。

**修复方向明确：把彩色 AE/WB 参数接入与码率同一套 NVM 持久化路径，并让 `startCamera` 不再覆盖已有用户值；主机侧同步增加 color domain 补写与"参数已被设备复位"提示。**
